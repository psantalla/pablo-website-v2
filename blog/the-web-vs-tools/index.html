The Web vs tools

  • February 5, 2026

I'm getting bombarded with WordPress vs Webflow these days.

The problem isn't the tools themselves. The problem is people choosing the tool over real technical knowledge. Learning the tool is fine, but understanding the Web is what sets you apart.

If we think of the Web as it really is—a set of rules for laying out content and multimedia in a browser, with optional interactivity—both WordPress and Webflow are just outdated toolboxes.

That said:

  • Webflow avoids proprietary language in the elements panel, empowering level-zero builders to grow into competent pros without having to spend ages figuring out that row settings are really just simple flexbox properties.
  • WordPress has a messy dashboard, which makes all the old-school devs feel nostalgic, but it’s been around for decades and solves scalability problems many tools can't.

And yet, both fall short. You need custom code. They let you do it, knowing their software won’t always cover all the capabilities a web browser has.

A couple of unique tools to think beyond the standard web builder:

  • Eleventy – precompile markdown into HTML layouts with zero JS dependencies.
  • Etch – build visually like a traditional page builder or use custom code, staying true to how the browser actually works. The output stays as stable and flexible as possible.

Tools for the Web follow the Web’s rules, not the other way around. Understanding the Web puts you a step ahead of any new feature or update in the ocean of web software.
